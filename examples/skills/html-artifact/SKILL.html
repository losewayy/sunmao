HTML artifacts

Use the HtmlArtifact tool for anything meant for a human to look at — plans, reports, checklists, design drafts, dashboards. Do not emit a plan.md when the deliverable is the document itself.

Producing

  1. Call HtmlArtifact with a [a-z0-9_-] slug and a complete HTML document. It writes .sunmao/artifacts/{name}.html and logs an Artifact event.
  2. Keep artifacts self-contained: inline CSS, no external network resources — renderers sandbox them (no outbound net, no storage, no parent DOM).
  3. template.html beside this skill is a minimal reviewable-plan layout: title, sections, and an annotation block at the bottom. Copy and adapt it.

Annotation round-trip (state.json)

An artifact is a two-way surface. When the human should review it:

  1. Emit the artifact from template.html (or include an equivalent <section id="annotations"> block).
  2. Tell the human the state path: .sunmao/artifacts/{name}.state.json.
  3. Annotations arrive as JSON — from the GUI island, the /annotate command, or a hand edit:
{
  "annotations": [
    {"section": "rollout", "note": "stage 2 first", "at": "2026-09-30"}
  ]
}
  1. On the next turn, Read the state file if it exists and fold the notes into the revision. Re-emit the artifact with another HtmlArtifact call (same name overwrites → a new version). Mark handled notes "resolved": true — never delete them.

The artifact is the shared document; state.json is the margin. Both stay plain files — no server, no database.
