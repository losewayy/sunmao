# Frontend components

The web and Tauri clients share the same embedded assets. React owns the command palette and image dialog through `src/overlays.tsx`; cmdk provides command filtering and keyboard selection, Base UI provides modal lifecycle and focus handling, and Floating UI DOM positions the existing popovers and tooltips. `src/model-picker.tsx` supplies the inline Base UI Combobox used by session, default-model and Fusion role selectors. `src/appearance.tsx` supplies controlled Switch, Slider, Select and RadioGroup controls in stable appearance-page slots. Existing CSS tokens and glass surfaces remain the styling source. The transcript, Native UI protocol, browser overlay coordination and Rust event protocol retain their existing boundaries.

## Development

Use Node 22 or newer. Install locked dependencies with `npm ci`, regenerate the embedded bundle with `npm run build`, then run `npm run check` and `npm test`. The check includes TypeScript and byte-for-byte verification of the generated files. Do not edit `crates/cli/src/serve/assets/ecosystem.js` or `ecosystem.licenses.txt` by hand. These two generated files are checked in so ordinary Rust builds and crate consumers do not require a Node runtime or an npm installation; CI verifies them against their sources and lockfile.

The bundle is a production IIFE with an explicit `window.SunmaoUI` bridge, loaded before the classic application scripts. React owns `ecosystem-root` and its portals in `palette` / `imv`, the appearance-page component slots, and mounted model-picker bodies; legacy scripts must not write into those subtrees. Ephemeral model roots return an unmount callback to the legacy popover owner, which runs it at removal. Leaving the appearance page unmounts its controls and releases Select portals and native overlay parking. Only legacy popovers carry `data-legacy-pop`; sharing the `.pop` style never grants legacy code ownership of a React portal. The replay parity harness deliberately skips this DOM renderer and continues testing the event fold. Component tests execute the actual embedded bundle against a DOM implementation; they are not visual or WebView acceptance tests.

The existing UI state object remains the source of truth: component changes call the application bridge, which applies and saves settings; server loads and resets update controlled props without triggering another save. Session-model selection retains a literal freeform choice, while default-model and Fusion-role selectors remain restricted to saved entries. Settings navigation remains navigation; theme modes use radio semantics.

All runtime dependency license texts ship in `ecosystem.licenses.txt`, also available through the shared resource route. License fallback provenance is recorded in `licenses/README.md`. The build does not fetch libraries or licenses from a CDN at runtime.
